# Bounded architecture authoring and neutral rendering

`architecture-design@1` covers Stage 01 boundaries, Stage 02 ownership/relationships,
Stage 03 data/interfaces, Stage 04 delivery, and engineering-spec decisions. A section
can be split by the caller into bounded named parts; the template supplies concerns,
not business scope or required row counts.

The existing bounded architecture functions from the M1 trial live in
`scripts/phase2/architecture_templates.py`. `prepare_architecture_section` validates
the frozen P1 projection and selects exact source IDs. `prompt_for` supplies selected
facts and full relevant earlier explicit records. Selected fields for a shared original
ID are identical across its authors; later answers are never injected into earlier prompts. `schema` / `validate` enforce flat records,
original references and matching operation-field identities. `render_architecture_section`
only formats records and gaps; a render is never an acceptance verdict.

Author output retains `section`, `services`, `objects`, `operations`, `fields`,
`states`, `policies`, `gaps`, and `notes`. Records select the corresponding neutral
card by their collection; there are no composition handles, nesting or variant tags.
All fields remain required within a supplied record. Unneeded collections stay empty.
Local schema object depth is at most three. Provider schemas are not needed.
Single requests stay within 60K tokens and outputs within 8K; aim around 4K output
tokens per part. Keep the existing two-repair limit and explicit gap freeze.

Review inputs use raw author records, facts selected by their referenced original IDs,
and pattern-card IDs. They do not include rendered documents or the full fact index.
OMR and isolated SQR remain the existing review roles; no extra review is created.

## Existing Stage/ESP format

Existing reader headings, table column names and accepted authority IDs are preserved.
`context["architecture_slots"][stage]` supplies author values for compatibility renderers.
Stage keys are `stage01`, `stage02`, `stage03`, `stage04`. Missing text is
`undecided: author decision required`; missing row collections are empty, never padded.

- Stage 01: roles, capability rows, decision/trace rows, forbidden-assumption rows,
  quality measurements, architecture/security/capacity text and diagrams.
- Stage 02: lifecycle and event records, entity/collaboration diagrams, named gaps.
- Stage 03: storage, technology alternatives, sensitivity, scenarios and graph edges.
- Stage 04: work packages, risks, actual verification/replay evidence, observability,
  identity/key decisions and an authored schedule. Rendering never produces a `pass`.
- ESP: source projections preserve undecided values; reader summaries never insert a
  product loop or architecture judgment. Engineering-specific author decisions use
  the `engineering` skeleton and policy records before review and delivery.

The installed `stage-03-design-defaults.json` filename remains for compatibility;
its four former answer arrays are empty. The new library is a separate versioned
asset. Existing frozen project outputs are not rewritten or regenerated by this
format upgrade. Old schema/contract generation helpers remain a compatibility
surface; they do not provide defaults for the bounded authoring route.

## Repository entry and declared runs

Use `python scripts/phase2/run_bounded_p2.py dry-run --config /external/config.json --out /external/new-dry`
then the same entry with `run --config /external/config.json --declaration /external/declaration.json --out /external/new-run`.
The entry wires the M1 author/freeze functions, the original OMR/SQR, shared transport
and one Journal. External directories contain declarations, configuration and output;
no experimental orchestration module is imported. API credentials come from
`OPENAI_API_KEY`, never a tracked config or retained prompt.

Configuration binds frozen P1/projection and calibration sources by path/SHA256;
selects original IDs/fields and architecture references for each section; declares
review group allowances; and names frozen architecture/D author sizing surrogates.
M3 uses the actual M2 author outputs, including their real T2 dispositions, instead of
smaller M1 proxies. Set `recompute_review_groups=true` and `require_fact_symmetry=true`.
The dry report retains exact prompt hashes, calibrated estimates, reservations and
`fact_symmetry` comparisons/violations. Each review section names applicable `fact_refs`;
records for other sections cannot be treated as facts that this author received.
D authors receive their own selected references with common-ID fields aligned.
Each section's operation-bound patterns receive its corresponding operation records.
After generation, review grouping is recomputed from actual raw outputs and cited
facts. It may reduce or move groups within the declared allowance, never increase
review calls; D remains at most four calls. Oversized work retains a gap.
A degraded section contributes only `<section> unavailable (T2)` downstream.
Raw validator text stays in call records/section diagnostics, not model-visible facts.
Older frozen degraded notices are normalized only in the model view, without
rewriting the frozen source or its hash.
When ESP lacks an old answer, its declared sizing surrogate is an unchanged existing
answer, labelled as such. It is not engineering work or a generation reuse.
The offline entry writes every author/reviewer prompt and estimate, includes ESP and
all reviews in the reservation sum, and records the original architecture gap scope.
For a different frozen project, `surrogates.sizing_source_config` binds the original
source project's configuration by path/SHA256. Offline prompts combine target P1
facts with unchanged source-case prior-record sizes. Review size wrappers retain
unchanged author answers but explicitly label their target-fact binding as
`cross-scenario-sizing-only`; original provenance remains in the immutable source.
This is an estimate, not a claim that those answers belong to the target project.
Both target prompts and conservative sizing prompts are retained, using the larger
estimate. The real run never reads these surrogates or imports their decisions.
It constructs no transport. Only a ready dry report bound to the same configuration
and declared clean repository commit can start the existing run functions.

For M2, requests remain <=60K and outputs <=8K, local schema depth <=3, at most two
same-section repairs, and at most two runs sharing the configured scenario `token_limit`. The existing
Journal's explicit `charged-pending` policy checks measured/conservative charges plus
pending reservations and the next reservation atomically. Old runs retain their original
reservation policy. Unknown completed usage consumes its upper bound and remains
labelled unknown; it does not become measured zero. Stop dispatch at a declared cap
and freeze original outputs with gaps. A cap is not permission to start another round.

The second run declaration binds the first result and its immutable Journal, lists
only previously unmet sections, and uses at most the verified remaining budget.
Use `dry-run --declaration /external/second-declaration.json` for its selected prompts.
Accepted first-run artifacts are retained with their original freeze lineage. No rejected
answer is supplied to a later run's author. D has at most four actual review calls across
the two runs, including transmission attempts; if those are consumed, retain D's current
gaps rather than generate an unreviewable replacement. Gap-decision dispatch is zero
in this entry, within the two-per-run ceiling; remaining P3 gaps use the existing P3 route.
Final combined artifacts bind both original freezes, without inventing another review.

Reviews contain only unchanged author records, their original ID-selected fact values
and pattern IDs. Source/citation metadata remains in the bound external subject, and
unreferenced prior object ownership is not copied into author prompts. Explicit groups
replace the former automatic greedy/all-choices splitting. Each named section needs its
own conclusion; absent conclusions or material defects reduce its delivery to T2.
Missing reviews never become acceptance. Each actual request still checks its current
size; an offline surrogate estimate is not a promise about later model output size.


## Repairing reference-only author input and an unstarted review

Each architecture collection adds new records for its section. Earlier identities are
reference-only: foreign keys and policy scopes may cite their exact IDs without
redeclaring the records. Duplicate IDs remain invalid; one diagnostic lists all observed
collisions, and local schema diagnostics retain their original code and field path.
Review packets include directly ID-referenced original author records and their cited
P1 facts, with exact source bindings. Unrelated author records are not attached.

A second declaration may list `reuse_authored` D sections whose original authors are
structure-accepted and whose review never started. The entry calls the existing
`generate_sections(accepted=...)` / `reuse_accepted` functions against the original
settled Journal in replay-only mode. Identical selected input, template and original
response binding remain required. A failed author or a previously reviewed/rejected
proposal cannot use this route; no author call or new generation mechanism is added.
The dry run retains both M1 sizing-surrogate prompts and exact reused-author review
prompts, reserving the larger estimate for each call. Declared groups must fit the
remaining cumulative budget and the existing D review-call ceiling. Unselected units
remain explicitly unreviewed T2 and do not satisfy complete review coverage.

## Request calibration and manual stop

For the exact calibrated endpoint/model, the approved request estimate is
`ceil((ceil(prompt_utf8_bytes / 2) + 4000) / divisor)`, initially `divisor=1.4`.
The calibration profile binds the measurement evidence SHA256. Compare every completed call's
conservative-bound/provider-input ratio, including after the initial three samples; reduce the divisor
to any smaller observed minimum for later reservations and review regrouping.
The shared transport writes each comparison and before/after divisor to evidence.
Completion uses measured provider tokens; cutoff/transport error uses the reserved
estimate plus8000. Provider input above60000 still stops dispatch; output above8000
remains rejected. Input at or below60000 that exceeds the estimate retains its
actual charge and lowers the divisor without terminating the run. The Journal
still stops at its declared total budget or deadline. Changed endpoint/model or output-calibration
drift disables calibration and restores byte accounting until recalibrated.

An operator monitors first-attempt diagnostics in the existing call JSONL.
When one validation error class occurs on first attempts in three distinct
sections that still fail after the existing bounded repairs, call
`GenerationJournal.stop_authors(run_id, reason=...)`, recording the three original
call IDs, all repair IDs, sections, error class and unresolved outcomes. Successful
repairs do not count; pending or unattempted repairs are not failed repairs. This is
one human action, not a new watcher, role or review. An already issued answer
settles normally. Do not terminalize the whole Journal for this author stop:
funded OMR/SQR tasks still run, including explicit gaps for stopped authors.
Hard transport, unknown-usage and declared wall/total limits remain in force.
Never restart the run or replenish its budget.

For the Owner-authorized M3 second acceptance, configure `protect_reviews=true`.
The existing Journal protects one 68,000-token slot (60K input plus 8K output) and
one call for each planned OMR/SQR packet before author generation. Every atomic
reservation checks charged plus pending usage, this call and all other unused
review slots against the declared cap. A review consumes its own slot once;
its transport resend uses only remaining unprotected funds and cannot displace
another review. Existing actual-size regrouping may release surplus unissued slots
after binding a complete review packet plan; it never adds packets or refunds a
dispatched call. Insufficient author/repair funds persist an author stop, including
across restart. No additional review or retry allowance is introduced.

Architecture inputs may name `prior_sections` and `prior_collections` to select
exact original predecessor records. Stage04 and engineering use explicit scoped
records instead of accumulated earlier prose. Author prompts list the available
IDs by identity family and original role labels. Invalid selected identities,
families or conflicting values fail locally before sending. Review packets retain
original answers and only cited original records that were available to that
author; a future technical record sharing a P1 object ID is not earlier input.

Use `frozen_upstream` for M3 second-acceptance offline sizing: same-case M2/M3
original architecture records, frozen architecture/index, raw D proposals and
measured call JSONL, all SHA-bound. Missing original answers remain missing;
no cross-case substitution, fabricated answer or old-output review is performed.
The report includes every prompt estimate, measured-call differences and missing
measurements, author reserves, protected reviews and repair contingency. Dry-run
readiness is input/budget evidence, not semantic acceptance. Audit verification
and explicit budget determination are required before the extra single run.
After GEO, any recurrence of displaced reviews, >60K nondispatch, the same
reference-error classes or author stop disabling funded reviews prevents PetClinic.
Otherwise run PetClinic once regardless of GEO's semantic review verdict. No
code changes during either scenario, no rerun. M4 stays paused until acceptance.

Compatibility renderers leave absent boundary scope `undecided` and access-pattern
rows empty. Only admitted authority records supply explicit access/index facts;
a generic lookup workload, traffic level or tenant index is not a template default.

The configured `token_limit` is the phase/scenario ceiling shared by both runs. Offline sizing, first-run declaration and second-run remaining budget use that same value; the second run cannot change scenario identity or raise its ceiling. Measured input at or below60K may exceed a calibrated estimate: retain actual usage, lower the divisor and continue, unless the Journal total budget or deadline is reached. This also applies after the first three completed calls.

`allowed_roles` retains each selected `user_role_or_actor` string verbatim,
including compound labels and punctuation. It is a source-context reference;
operation effects/policies still state which actor can act under the cited
original authority. Splitting a label does not establish a new registered role,
and copying it does not grant every named actor permission.

A second-run subset can use the same immutable cross-scenario size-only proxies
when first-run outputs are missing. Reservations are compared with the original
scenario ceiling minus first-run charge. This path cannot rebind reused authors
and never sends source-case proxy answers as target-case content.
