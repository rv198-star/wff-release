# D interaction generation runtime

Use the frozen P1 Authority and its six-category projection, plus separately frozen architecture/API documents. Original JSON bytes and SHA-256 are the source boundary. A projection or a selector does not establish source acceptance. Preserve the selected input's acceptance scope and unresolved gaps.

## Input and execution

`phase2.interaction_templates.prepare_section` reads the projection against `p1_raw`, `expected_p1_sha256`, and `logical_id`. Supply one of the ten library section IDs and a `selection` map from projection categories to original P1 IDs. Architecture inputs are dictionaries containing `raw` bytes, `expected_sha256`, `logical_id`, and `selectors`; each selector names only the original `id_pointer` and `value_pointer`. Never substitute new identities or rehashed adapter values. Select only the relevant original rows per section; the complete projection is an offline index.

The versioned `scripts/phase2/data/interaction-design-v1.json` contains section skeletons, neutral pattern cards, bounded slots, applicability guidance, and fixed wording. It covers the eleven interaction patterns plus a delegation-rule structure. Agentic selects patterns, parameter IDs, optional trims and text; code renders their parts, original source names/attributes/states, numbering, cross-references, provenance and claim ceilings. Missing permissions or transitions remain undecided. Custom text requires its reason. A trim or deliberate deviation uses `slots.reason`; ordinary use does not require it. Evidence checks shape, references, limits and rendering; semantic quality remains with the two existing reviewers.

Use the existing `common.semantic_generation_journal.GenerationJournal` with phase `P2`. Create a run with the declared `max_calls`, `max_tokens`, and `wall_seconds`; bind its snapshot to the prepared packets and its contract to the library digest. Pass `generate_sections` the packets, library, Journal, context (`run_id`, `wp`, `scenario`, `model`, `measurement_kind`), transport `send`, new external output directory, `max_repairs` from 0 to 2, and explicit `failure_level` T1/T2. A run may not repeat a section identity.

Use `common.bounded_model_call.dispatch` and `common.bounded_response_stream.ResponsesTransport` for D and P3. The host supplies its existing endpoint, credential callback, model, external evidence folder and declared absolute deadline. The transport makes one request with streaming, an 8,000 output request limit and no provider schema or tools. There are no hidden retries. P3 uses Journal phase `P3` rather than relabeling implementation work as P2.

For a calibrated endpoint/model, the stream estimates visible output as the number of SSE text delta events ×1.02, rounded up, plus 64 units per output item and a 1,024-token reserve for opaque reasoning (replaced by larger streamed/reported reasoning). Unstreamed text retains byte counting. Calibration must bind the exact endpoint/model and retained evidence SHA256; unknown or changed channels/models use byte counting until recalibrated. Every final response compares the raw visible delta count with provider output tokens minus reasoning tokens: absolute relative deviation over3%, missing comparable usage or a changed model switches subsequent calls back to byte counting and records `calibration-check.json` plus the call JSONL report. Opaque reasoning remains an estimate, not proof of server cancellation. At the first event reaching8,000 estimated tokens the caller closes the stream, preserves received bytes and partial text, and records a rejected section with known conservative charge=request estimate+8,000. Completed responses retain provider-measured usage; fallback never rewrites historical records.

`send(prompt, *, max_output_tokens=8000)` returns unchanged `raw`, model, usage and finish status; `finish_reason="stop"` means complete and below the caller limit. HTTP/stream errors consume the full request upper bound + 8K reservation, recorded as `transport-error-upper-bound`; remote execution remains uncertain. Resend the same section at most once, counting every dispatch; two transport failures in a section leave T2 and other sections continue. The third transport error in the run stops dispatch and requires an Owner report. Declared call/token/wall caps still apply to resends; other unknown usage stops the run. This is finite network recovery, not an extra semantic review or a reset of the section repair limit. Section overflow or truncation consumes the same section's existing repair allowance: simplify the output and omit the truncated answer from the next prompt. At most two repairs; still unsuccessful becomes T2 while other sections continue. No extra semantic review rounds: a rejected OMR/SQR response with known cost leaves complete-review proof unavailable; the other existing reviewer may still run in isolation, and authorized bounded v2 closeout retains the missing-review T2 gap. Before dispatch, calibrated request tokens are ceil((ceil(UTF-8 prompt bytes/2)+4,000)/divisor) under60,000; the approved evidence-bound profile starts at divisor1.4 and reduces it to the minimum conservative-bound/provider-input ratio in every completed call, including after the initial three samples. Each comparison and divisor is retained in `request-calibration-check.json` and call JSONL. Completion still charges measured usage, and measured input over60K stops; uncalibrated/fallback transports retain bytes+4,000; oversized input stays a section gap without a model call. Author and reviewer prompts target about4,000 output tokens or less per section, with brief reasoning. This is a content-design target, not another gate or a filling quota; the existing 8K output ceiling is unchanged. Keep the highest-decision-value detail and explicit gaps rather than repeating source facts in prose.

Each section requests one flat object with `section`, `uses`, `custom`, `gaps`; each use has only `pattern`, `params`, `trim`, `slots`. The local schema has three object layers and tolerates singletons and a JSON fence before strict validation. Diagnostic repairs include only that section's previous unaccepted answer from the same run. Structural diagnostics retain the exact JSON pointer and error code; an omitted required field remains rejected, and an untrimmed use must explicitly include `trim: []`. After two unsuccessful repairs, the section becomes a T1/T2 gap and other sections continue. No extra planner, reviewer, controller or recovery layer is used.

## Reuse, review and freeze

Pass accepted prior artifacts and their original Journals via `accepted`. Reuse requires identical selected input and library, a settled original raw response, and its committed draft binding. Re-rendering must reproduce the exact accepted artifact. Changed inputs are new work; unaccepted old answers cannot be imported. Reuse writes `reuse.jsonl` and does not create a new call or duplicate costs.

`review_and_freeze` uses the existing P2 final review reader and exactly OMR then SQR. SQR receives the same original subject, facts, choices and gaps, with no OMR response. The reviewers return a shallow verdict/findings/notes object; code generates finding IDs and receipts. Retain semantic defects as review-bound findings with their consequences and downstream decision needs. There is no coverage quota, additional adoption round or human approval claim.

`prepare_review_packets` accepts declared section groups. With `recompute_groups=true`, it sizes the actual original author outputs and chooses fitting ordered groups within that allowance, including a single group when it fits. It never adds calls. D authors receive their own ID-selected facts, including their bound architecture operations; shared IDs retain consistent original fields. Each review section names its applicable original fact IDs; a fact belonging only to another section is not an omitted author input. Each packet contains only those sections' original author answers, their ID-selected fact values and pattern IDs; it contains no rendered document or full fact index. Source metadata remains in the retained subject. If a declared packet exceeds60K, simplify its selected input or declare smaller groups before dispatch. The former automatic greedy splitting and repeated all-document choices have been removed. Execute the declared OMR packets, then identical packets for isolated SQR; no OMR response enters SQR. Keep every original settled call, prompt/input digest and finding. Every named section requires an explicit conclusion; document PASS cannot fill a missing conclusion.

For an explicitly authorized bounded closeout, use `freeze_bounded_interaction`: preserve original author content and actual receipts, reduce affected sections to T2 for material findings, absent conclusions or missing/rejected review coverage. There is no new review or budget reset. M2's repository entry and cumulative budget are documented in `architecture-generation.md`; its D review cap is four actual calls including any resends across both runs. Old frozen input remains read-only compatible.

The complete-review v1 freeze binds `interaction-design.json`, `interaction-design.md`, `interaction-subject.json` and `interaction-review.json` in `interaction-freeze.json`. Record the manifest SHA-256 externally. P3 uses `load_frozen_interaction(path, expected_sha256=...)`, which verifies file hashes, subject/review bindings and claim ceilings. The scope is **interaction-design-only**, not complete P2 acceptance or permission to regenerate P1/P2. Unresolved gaps and explicit delegation rules travel with the frozen payload into P3 decisions.

## Evidence and offline replay

Keep output and Journal directories outside the code repository. `calls.jsonl` records each dispatch, including failed or unknown executions, using the rectification call fields plus input binding and raw/prompt paths and SHA-256. `call_metrics` excludes fixtures by default; attempt denominators use run, section and input identity. Unknown usage remains unknown, never zero. Active-cutoff and transport-error charges are listed separately from provider-reported totals and carry the estimator details; aggregate charged tokens include all known charges. `transport_attempt` distinguishes a resend from a content repair; first-call acceptance counts the original dispatch, never the successful resend as a new first attempt. Report delivered/total sections and custom/(pattern+custom) blocks from the assembled payload separately.

`python scripts/phase2/interaction_generation.py` prints the library version, section/pattern counts and local schema depth without a provider call. For deterministic recorded-text replay:

```sh
python scripts/phase2/interaction_generation.py --replay-plan /external/replay-plan.json --output-dir /external/new-replay
```

The replay plan contains `p1_authority` (file path), `expected_p1_sha256`, `logical_id`, `run_id`, `wp`, `scenario`, declared `max_calls`, `max_tokens`, `wall_seconds`, `max_repairs`, `failure_level`, and `sections`. Each section has `section`, `selection`, and optional `architecture` documents (`path`, `expected_sha256`, `logical_id`, `selectors`). `replies` is the ordered list of recorded transport response dictionaries. Set `review=true` only when it also includes the two recorded review answers. Fixture records explicitly identify `measurement_kind=fixture`; their token counters are replay inputs, not measured model cost or real semantic validation.

For bounded closeout, call `review_and_freeze(..., collect_only=True)` for the same original OMR/SQR. On completion or a declared cap, call `freeze_bounded_interaction` once; it performs no model calls. The v2 manifest additionally binds `interaction-authored.json`, `interaction-review-inputs.json` and the neutral `interaction-template.json` snapshot. Every retained receipt is checked against its settled Journal call and raw response; absent or invalid receipts remain named evidence gaps. Loader checks preserve author content and mechanically recompute T2 dispositions. Keep generation acceptance metrics separate from reviewed delivery metrics.


When a review never started, the repository entry can reuse a structure-accepted
original author through the existing exact Journal replay, with identical input and
template bindings. `reuse_authored` lists those sections in a second-run declaration;
it never permits reuse of a failed or previously reviewed/rejected proposal. Both
M1 sizing surrogates and the unchanged actual review input are checked offline, using
the larger reservation per call. This resumes only the unmet review work within the
two-run, cumulative token and four-D-review limits. Omitted sections remain unreviewed
T2; partial review coverage is not complete milestone acceptance.

Degraded downstream notices contain only the section identity and T2 unavailable
status. Raw validation diagnostics stay in the external call log or
`section-diagnostics/<section>.json`, including local rejections without a dispatch.
The operator's three-distinct-section first-attempt stop rule (counting only sections still failing after bounded repairs) and request calibration
are specified in `architecture-generation.md`; they apply to the shared D/P3 caller.
