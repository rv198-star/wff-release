# wff-impl-verification SOP

1. Read ActionCard verification obligations.
2. Generate or refresh test surfaces. Preserve identifier values according to the accepted P2 field type: UUID normalization is allowed only for `uuid`; legacy/current-system `string` and `integer` identifiers must retain their declared semantics across request fixtures, baseline rows, and persistence probes. Accepted P2 type authority takes precedence over OpenAPI types mechanically inferred from placeholder examples; genuine accepted-P2 type conflicts remain fail-closed. Durable update baselines must represent accepted pre-update state and must not collide with accepted create replay identity. Accepted table-backed read models/current-system snapshots with no writer aggregate still require validation-only seed rows when their exact operation is read-only; project only accepted table fields and never infer write authority or production-data truth from those rows. For the first positive insert/upsert invocation in a scenario, remove only a validation-only baseline row that conflicts on an accepted P2 unique request key; do not apply that cleanup to negative conflict evidence or replay attempts. A caller-field negative fixture for a replay-safe write must also avoid reusing a prior successful replay identity that would short-circuit validation through return-existing; when the invalid field is outside the replay key, vary only a type-compatible caller-request/idempotency identity component and preserve required foreign/context identity, while explicit replay/conflict lanes remain unchanged. Not-found path probes must preserve the accepted identifier type so they exercise 404/not-found semantics rather than input validation. Persistence round-trip probes must use accepted P2/schema type-compatible columns and must not cross-map UUID/string/integer identifiers merely because names are similar. Caller-input negative fixtures must prefer the exact semantic request field named by the error-code vocabulary over a compound field that merely contains the same token (for example `invalid_decision` targets `decision`, not `decision_request_id`). Negative stale/version-conflict fixtures must mutate an accepted version-like request field that actually exists rather than inventing a parallel naming alias, and `stale_version` is accepted conflict-family evidence. Generated API routing must preserve the frozen operation-local OpenAPI error-code/status mapping before applying any generic runtime fallback; do not globalize one operation's status semantics to another operation that reuses the same error code. Full-suite SQL probes must use deterministic same-type identities isolated from runtime baseline rows instead of weakening constraints, skipping SQL evidence, or deleting accepted baseline data. The generated S3 kernel test must also exercise shared binding-selection and fail-closed boundary primitives that remain inside the business-runtime coverage denominator.
3. Run the requested verification mode.
4. Record skipped, blocked, failed, and passing evidence separately. Preserve upstream P1 requirement/AC/constraint lineage (`P1-REQ-*`, `P1-AC-*`, `P1-CON-*`) as traceability context and union multiple accepted P1 resolution rows for the same operation instead of overwriting lineage, but evaluate Trace identity reuse/abuse against the current P3 row's own primary source/trace identity; shared upstream lineage across legitimate read/write realizations is not by itself identity abuse.
5. Reroute missing implementation/runtime proof back to P3 remediation.
6. Hand off evidence to P4 without inflating the claim ceiling.
